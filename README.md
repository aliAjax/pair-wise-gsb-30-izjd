# 油品配送计划（汛期断网调运 · 领号续办）

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 逻辑自检：`./node_modules/.bin/esbuild test/sim.ts --bundle --platform=node --format=cjs --outfile=/tmp/sim.cjs && node /tmp/sim.cjs`（33 项断言全过）

## 核心模型

配送单、油罐车、油站库存统一挂“领号（Ticket）”流水，每一步操作（建单/派车/装车/发车/到站/库存调整）
先领号再落账，数据持久化在 localStorage（`hxwlfront-19-flood-dispatch-v1`）。

1. **断网派车，回网回传**：断网时领号标记为“断网领取”并进待回传队列，不阻塞现场操作；回网点
   “拉取油库验收结果并对账”，按“先到油库、后到平板”的顺序逐笔补登验收结果（回传顺序不一致也能对上）。
2. **同车抢占对账**：平板先登记待复核记录，回网后按油库验收结果与首次确认时间裁决——在先单据
   保住罐车，输方回滚到派车前状态、释放罐车；**已发车单据沿用派车首次确认领号，受保护不再调整**。
3. **半份装车恢复**：装车提交失败时油库已落账的吨数保留（半份），单据停在“装车中”；从
   **最近完整领号（派车首次确认领号）** 回滚半份吨数后续办补装。
4. **库存联动重算**：库存每次变动，所有未发车单据的“未装车占用/缺口”按建单先后 FIFO 重算，
   页面实时列出**平板待复核记录**与**库存缺口清单**。
5. **发车沿用依据**：发车领号记录 `basisTicketId` 指向派车首次确认领号，卡片领号链与台账中可见。

## 页面区域

- 顶部：在线/断网开关、拉取油库验收并对账、重置演示数据
- 指标：配送单 / 待复核 / 缺口单 / 待回传领号
- 左列：领号建单、油库库存表（可调账；调账自动触发未装车占用重算）
- 右列：待复核记录（可单笔恢复或整批对账）、缺口清单、配送单续办卡片（派车 / 装车 / 提交失败模拟 / 发车 / 到站）
- 底部：单据阶段分布、已对账记录、领号流水台账（可看每笔领号的回传状态与油库验收回执）

## 演示路径建议

1. 先点“拉取油库验收结果并对账”：种子中的抢占待复核（本单 07:35 早于对方 07:38）判定保车。
2. 断网后新建单据并派车 →“模拟同车抢占登记”→ 回网点对账，观察输方回滚、罐车释放，再重新派车。
3. 装车时点“提交失败（半份）”，在待复核区“从最近完整领号恢复”，随后补装、发车、到站确认。
4. 在库存表调入/调出库存，观察未装车占用与缺口清单实时变化。
